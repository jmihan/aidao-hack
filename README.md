# Адаптация параметров LDPC-кодов для квантовой криптографии

## О проекте

Данный проект представляет собой решение задачи в рамках олимпиады AIDAO по адаптации параметров LDPC-кодов (Low-Density Parity-Check) для системы квантового распределения ключей. Основная цель — разработать модель искусственного интеллекта, которая в режиме реального времени подбирает оптимальные параметры кода `{R, s, p}` для эффективной коррекции ошибок в квантовом канале связи.

### Контекст задачи

В системах квантовой криптографии ключевым этапом является коррекция ошибок, возникающих при передаче сигнала. Для этого используются LDPC-коды, параметры которых необходимо гибко настраивать в зависимости от изменяющегося уровня ошибок в канале (QBER - Quantum Bit Error Rate). Модель должна анализировать характеристики квантового канала и состояние оборудования, чтобы предложить оптимальные параметры:

*   **R** — отношение полезных битов к длине блока.
*   **s** — количество укороченных узлов.
*   **p** — количество проколотых узлов.

Эффективное решение позволяет минимизировать количество итераций декодера, сократить объем передаваемой служебной информации и уменьшить число дополнительных раундов коррекции, что в итоге увеличивает длину финального секретного ключа.

## Методы и эксперименты

Для решения задачи было исследовано три различных подхода, каждый из которых обладает своими преимуществами и основан на разных гипотезах.

### 1. Прогнозирование временных рядов с помощью PatchTST

**Гипотеза:** Ключевым фактором для выбора параметров кода является будущий уровень ошибок `E_mu_Z` (QBER). Мы можем рассматривать входные данные как многомерный временной ряд и использовать современную Transformer-архитектуру PatchTST для прогнозирования `E_mu_Z`.

**Реализация:**
1.  **Подготовка данных:** С помощью скрипта `src/utils/preprocess_tabular.py` генерируется набор признаков, включающий лаги, скользящие статистики и взаимодействия. Данные разделяются по сессиям (`id`) в хронологическом порядке для обучения и валидации, чтобы избежать утечек данных из будущего.
2.  **Модель:** Используется **PatchTST** — эффективная Transformer-модель, которая обрабатывает временные ряды не по точкам, а по "патчам" (подпоследовательностям). Это позволяет ей улавливать как локальные, так и глобальные зависимости в данных.
3.  **Обучение:** Процесс обучения управляется через `src/train_model.py` с использованием фреймворка Hydra для гибкой конфигурации эксперимента.
4.  **Предсказание:** Скрипт `src/predict_model.py` использует обученную модель для прогнозирования `E_mu_Z`. Затем на основе этого прогноза применяется детерминированная эвристика (с использованием экспоненциального скользящего среднего) для выбора оптимальных параметров `{R, s, p}`.

### 2. Двухэтапная модель на основе CatBoost

**Гипотеза:** Вместо прогнозирования промежуточной величины (QBER) можно напрямую предсказать оптимальные параметры `{R, s, p}`, которые использовались в исторических данных, рассматривая задачу как классическое машинное обучение.

**Реализация:**
1.  **Подготовка данных:** Скрипт `src/utils/preprocess_tabular_for_catboost.py` создает богатый набор признаков, включая контекстные, временные, и агрегированные статистики.
2.  **Этап 1: Предсказание R:** `R` рассматривается как категориальная переменная. Обучается модель `CatBoostClassifier` (`src/train_r_catboost.py`) для предсказания наиболее вероятного класса `R`. Для повышения стабильности редкие классы `R` были объединены.
3.  **Этап 2: Предсказание s:** `s` рассматривается как непрерывная переменная. Обучается модель `CatBoostRegressor` (`src/train_s_catboost.py`). Важной особенностью является то, что предсказанное на первом этапе значение `R` используется как один из признаков для этой модели.
4.  **Предсказание:** Скрипт `src/predict.py` последовательно применяет обе модели: сначала предсказывает `R`, затем, используя этот результат, предсказывает `s`. Параметр `p` вычисляется как `4800 - s`.

### 3. Оптимизация через суррогатную модель (CatBoost)

**Гипотеза:** Конечная цель — минимизировать количество раундов коррекции (`N_EC_rounds`). Мы можем построить "суррогатную" модель, которая предсказывает `N_EC_rounds` на основе состояния канала *и* предложенных параметров `{R, s, p}`. Во время инференса можно выполнить поиск по сетке параметров, чтобы найти комбинацию, минимизирующую предсказанное значение `N_EC_rounds`.

**Реализация:**
1.  **Модель QBER:** Поскольку на этапе предсказания истинный `E_mu_Z` неизвестен, сначала обучается модель `CatBoostRegressor` для его предсказания (`src/train_qber_model.py`).
2.  **Суррогатная модель:** Обучается `CatBoostRegressor` (`src/train_surrogate_model.py`) для предсказания `log1p(N_EC_rounds)`. В качестве признаков используются все параметры состояния канала, а также сами параметры `{R, s, p}`.
3.  **Предсказание:** Скрипт `src/predict_surrogate.py` реализует сложную логику:
    *   Для каждого фрейма предсказывается `E_mu_Z`.
    *   На основе предсказанного QBER применяется стратегия "бюджета риска": для высокого QBER поиск `R` ограничивается низкими значениями, а для низкого QBER — высокими.
    *   В ограниченном пространстве параметров `{R, s}` выполняется поиск. Для каждой комбинации суррогатная модель предсказывает `N_EC_rounds`.
    *   Выбирается комбинация `{R, s, p}`, которая минимизирует предсказанное число раундов.

## Как использовать

### 1. Установка

Для обеспечения полной воспроизводимости рекомендуется использовать Docker.

1.  Клонируйте репозиторий:
    ```bash
    git clone <URL репозитория>
    cd <имя папки>
    ```
2.  Поместите файл с данными `frames_errors.csv` в директорию `data/raw/`.
3.  Запустите скрипт для сборки Docker-образа и входа в контейнер:
    ```bash
    bash start_docker.sh
    ```
    После выполнения этой команды вы окажетесь в командной строке внутри контейнера. Все последующие команды выполняются из него.

### 2. Подготовка данных

В зависимости от выбранного подхода, запустите соответствующий скрипт препроцессинга.

*   Для **PatchTST**:
    ```bash
    python src/utils/preprocess_tabular.py
    ```
*   Для моделей **CatBoost** (двухэтапной и суррогатной):
    ```bash
    python src/utils/preprocess_tabular_for_catboost.py
    ```
    Скрипты создадут обработанные датасеты в папке `data/processed/`.

### 3. Обучение моделей

*   **PatchTST:**
    Обучение запускается одной командой. Все параметры настраиваются в файлах `.yaml` в директории `conf/`.
    ```bash
    python src/train_model.py
    ```
    Результаты обучения, включая чекпоинты и артефакты для инференса, будут сохранены в директорию `outputs/`, путь к которой генерируется Hydra автоматически.

*   **Двухэтапная модель CatBoost:**
    Необходимо последовательно обучить две модели. Для подбора гиперпараметров используется Optuna.
    ```bash
    python src/train_r_catboost.py --n-trials 50
    python src/train_s_catboost.py --n-trials 50
    ```
    Обученные модели (`.cbm`) и артефакты (отчеты, графики) будут сохранены в директорию `models/`.

*   **Суррогатная модель CatBoost:**
    Также необходимо обучить две модели.
    ```bash
    python src/train_qber_model.py --n-trials 50
    python src/train_surrogate_model.py --n-trials 50
    ```
    Модели будут сохранены в директорию `models/`.

### 4. Генерация предсказаний

*   **PatchTST:**
    Укажите путь к директории с результатами обучения, созданной Hydra.
    ```bash
    python src/predict_model.py <путь_к_папке_hydra_outputs>
    ```
    Файл `submission.csv` будет создан в корне проекта.

*   **Двухэтапная модель CatBoost:**
    ```bash
    python src/predict.py
    ```
    Файл `submission.csv` будет сохранен в `submissions/submission_final.csv`.

*   **Суррогатная модель CatBoost:**
    ```bash
    python src/predict_surrogate.py --t1 0.01 --t2 0.08
    ```
    Файл `submission.csv` будет сохранен в `submissions/`. Имя файла будет содержать использованные пороги `t1` и `t2`.
